# Computational complexity of algorithms
- **Понятие времени работы алгоритма:**
	- Время работы программы выражается формулой:
		- $T = k \cdot t$
		- $k$ — количество выполненных элементарных операций.
		- $t$ — время выполнения одной такой операции.
	- В теории сложности физическим временем $t$ пренебрегают, так как оно привязано к конкретному вычислительному устройству (процессору, памяти).
	- Анализ фокусируется на функции $k(n)$, которая отражает количество характерных операций в зависимости от размерности входных данных $n$.

- **Математическое определение O-нотации:**
	- Алгоритм имеет сложность $O(f(n))$, если его функция роста $k(n)$, начиная с определенной точки, ограничена сверху функцией $f(n)$ с точностью до постоянного множителя.
	- Формальное условие: существуют положительные константы $C$ и $n_0$ такие, что:
		- $k(n) \le C \cdot f(n)$ для всех $n \ge n_0$.

- **Основные классы вычислительной сложности:**
	- Поведение функций при стремлении $n$ к бесконечности определяет асимптотическую сложность алгоритма.
	- **Константная сложность $O(1)$:**
		- Количество действий фиксировано и не зависит от объема входных данных.
	- **Линейная сложность $O(n)$:**
		- Объем вычислений растет строго пропорционально размеру задачи.
	- **Квадратичная сложность $O(n^2)$:**
		- Время выполнения увеличивается пропорционально квадрату от объема данных.
	- **Экспоненциальная сложность $O(2^n)$:**
		- Количество операций удваивается при добавлении каждого нового элемента данных.
	- **Полиномиальная сложность $O(n^k)$:**
		- Описывает сложность в виде многочлена степени $k$. При анализе учитывается только старшая степень, а коэффициенты и младшие члены отбрасываются:
		- $a_k n^k + a_{k-1} n^{k-1} + ... + a_1 n + a_0 \implies O(n^k)$

- **Критерии выбора характерной операции:**
	- Подсчет сложности ведется по наиболее частой или наиболее трудоемкой операции в коде.
	- Если в алгоритме сложения и умножения распределены поровну, за характерную операцию принимается умножение (как более ресурсоемкое).
	- Если сложений кратно больше, чем умножений, подсчет ведется по операциям сложения.
	- Все разнородные действия внутри одного цикла, зависящего от $n$, могут объединяться в одну обобщенную операцию, а сложность считается по числу итераций этого цикла.

- **Практическое значение асимптотик при масштабировании:**
	- Игнорирование констант обосновано тем, что разницу в количестве операций в несколько раз (например, между $n$ и $2n$) можно компенсировать обновлением аппаратного обеспечения или распараллеливанием задач.
	- При квадратичной сложности $O(n^2)$ покупка более мощного оборудования не позволяет эффективно обрабатывать сверхбольшие массивы данных.
	- При экспоненциальной сложности $O(2^n)$ увеличение мощности процессора даже в $100$ раз сдвигает предел доступной размерности задачи $n$ всего на несколько единиц, что делает такие алгоритмы неприменимыми для больших входных данных.
